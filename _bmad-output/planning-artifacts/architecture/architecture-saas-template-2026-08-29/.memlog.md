- (decision) AD-1 Paradigm: layered monolith (routes → services → models/session → DB) + Refine dataProvider → hooks → pages; Transaction Script services, event-published audit via EventBus (InProcess/NATS) — ratified from src/main.py and docs/ARCHITECTURE.md
- (decision) AD-2 UserProfile 1:1 separate table user_profiles (PK=user_id, FK users.id ON DELETE CASCADE, common columns + custom_data JSON) — prevents merging into users hot path and keeps blast radius off workspace.py
- (decision) AD-3 custom_data uses RFC 7396 JSON Merge Patch: PATCH shallow-merge, null deletes key, PUT replaces bag, bounded 16KiB/50 keys — prevents ad-hoc merge strategies diverging
- (decision) AD-4 Extension seam: backend adds column + Pydantic field + Alembic migration only; frontend adds optional field to UserProfile type — generic ProfileService/accessor not edited — prevents forks touching shared helpers
- (decision) AD-5 API/auth: JWT via get_current_user, workspace co-membership guard for GET /users/{id}/profile (else 404), GET /auth/me always embeds profile (lazy get_or_create), no org-wide enumeration — prevents leaking PII across workspaces
- (decision) AD-6 Frontend contract: UserProfile = declared fields + custom_data + & Record<string,unknown>, getProfileField column-first then custom_data, useProfile/useUpdateProfile via useCustom relative to /api/v1, /settings/profile via Refine form primitives — prevents hand-rolled fetch or divergent accessor
- (decision) AD-7 Lifecycle/audit: profile.updated and user.deleted published on audit.entry.created (existing NATS JetStream SAAS_TEMPLATE workqueue), PII never in logs, export is sync bundle (user+profile+memberships+counts), delete is atomic hard-delete with FK cascade and session revocation
- (decision) AD-8 No Agent coupling: UserProfile seam must not be reused for future Agent/AgentProfile (separate agents/agent_profiles tables) — prevents polymorphic shared table
